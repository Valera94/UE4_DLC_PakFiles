# Логика Pak файлов и принцип архитектуры для DLC...
1 - Необходимо иметь первый "Pak_0" в качестве пустого фрагмента, где после загрузки Hud у клиента необходимо начать проверку актуальности текущей версии.
2 - Главное меню устанавливаем в "Pak_1" что бы мы могли менять Widgets если нам нужен другой вид или визуал.
3 - Контентные ресурсы так же разделяются на отдельные "Pak_index".

# Версионирование проекта.
### Пример: "version": "1.2.3.42"

MAJOR — крупные изменения (новая глава, новая механика), могут требовать полной переустановки DLC.<br/>
MINOR — новые фичи/уровни, обычно совместимы с текущей базой. <br/>
PATCH — исправления багов, баланс, мелкие правки.<br/>
BUILD — номер сборки, который можно автоинкрементировать при каждом CI/CD-билде, чтобы отличать тестовые сборки.<br/>
